## Summary

Copying QR characters into editors can lose their layout. Codex built Aqrobat
with deterministic text/emoji generation, image and styled-text exports, a static
demo, private package/CLI, and an unpacked Make → Save → Insert extension.
Product 0.4.2 and its three downloads remain unchanged by this research.

Readable, portable prose QR with normal-phone acceptance remains unsolved.
This session adds one unchanged native regular-black text PNG that returns
exactly `https://example.com/` in ordinary ZXing default and baseline. Those are
the same implementation; jsQR, default OpenCV, ArUco, macOS Vision and default
ZBar fail it. A second, whole-word full payload fails every ordinary profile.
Earlier bold/styled prose, uniform-black ASCII and configured-reader TXT/HTML
proofs remain separate. Ryan's earlier full PNGs failed both Samsung scanners;
there are no new phone results or successful phone candidates.

The local self-contained handback and safe checkpoint are in
`docs/research/prose-qr/session-2026-10-09/`. No manual deployment or new host is created. Existing GitHub Pages automation
is configured to publish this branch, so branch backups automatically rebuild
the existing site. Pages settings were not changed. The delivery clarification
is in `docs/research/prose-qr/session-2026-10-09-delivery/`.

## Deviations

The research moves from negative jsQR native selected-run objectives to larger
native-word density and separate ZXing sampled-symbol diagnostics, with fresh
preregistrations and unchanged ordinary acceptance profiles. The diagnostic
error-reporting profile can change search/termination and is never counted as
ordinary acceptance or passive-equivalent output. Source geometry is used only
in rendering and post-return diagnostics, never pixel repair or forced extraction.

Retained errors include the initial missing-matrix partial capture; a reserve
abort and detector-denominator assertion; a DP terminal-space rejection; a
partial four-config producer followed by an exclusive EEXIST; an eight-byte
reader-wrapper buffer mismatch; and a 120MB stdout transport abort. Fresh
read-only byte transport resumes the saved PNG without rerendering. Phase16's
incorrect manual error reports are explicitly superseded by its preserved
erratum, not counted as genuine capture failures. Report-only repair and browser
checker errors also remain. See HARNESS-NOTES.md for exact custody distinctions.

A research-only pinned ZBar runtime is added with its LGPL license, original
package, named source archives and build-source references. No product/npm
runtime dependency or installed font changes. Raw upstream formatting and raw
JSON results are preserved separately; narrow Git attributes apply only to
specific original upstream/build-output files.

## Known issues

One-engine recovery is not independent ordinary-reader acceptance. Phase14's
source is 257 native14px rows across 3600px, with repetitive words and isolated
`i`; phase28 is whole-word material with no recovery. Neither is coherent prose,
portable paste or owner-approved full-document legibility. Native excerpt
inspection and conservative ink-bound checks have narrower scope.

Complete isolated diagnostic finder masks do not transfer automatically to a
full payload or surrounding text. Larger native letters and simpler context
lexicons remain negative. Earlier full-resolution native span/ray failures are
preserved; these findings do not prove universal impossibility.

No new Samsung/phone/print observations. User's earlier failure denominator and
viewing conditions remain unspecified. Extension/email review, emoji atlas,
project migration, independent payload recovery and eventual phone acceptance
remain separate unfinished work.
