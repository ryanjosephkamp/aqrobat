## Summary

Copying QR characters into editors can lose their layout. Codex built Aqrobat
with deterministic text/emoji generation, image and styled-text exports, a static
demo, private package/CLI, and an unpacked Make → Save → Insert extension.
Product 0.4.2 and the original downloads remain unchanged by this research.

Readable prose QR recovery remains unsolved. Ryan's earlier full PNGs fail both
Samsung scanners. Earlier styled-prose and uniform-black ASCII/TXT proofs remain
separate configured-reader results. Phase 04 preserves 109 failed text/display
views; phase 05 preserves 40 failed native captures and its perfect-center
counterexample. No new phone acceptance is claimed.

Phase 06 isolates native-letter finder geometry before another full-QR sweep.
It retains 39 incomplete finder layouts with no encoded payload. All return
incorrect ordinary locator geometry. Native-pixel word feedback and smaller row
seams improve center-axis continuity, but passive inspection of two retained text
examples finds no correctly sized scored candidate near the intended centers.
The [checkpoint page](https://ryanjosephkamp.github.io/aqrobat/docs/research/prose-qr/phase-06/)
explains this failure without presenting a failed grid as phone candidates.
[Evidence and custody](https://github.com/ryanjosephkamp/aqrobat/tree/codex/aqrobat-foundation/docs/research/prose-qr/phase-06)
include all outcomes, sources, repairs and a safe continuation prompt.

## Verification

Phase 06: 39 native finder captures, zero intended locator geometries, 39 exact
immediate native repeat PNGs. Ten conventional full-QR controls pass three fixed
profiles (30 attempts); ten solid finder triplets locate correctly. Candidate
finder-only layouts contain no payload and are not counted as failed link scans.
One of 40 unique planned cases is rejected before native capture for width.

A separate read-only replay verifies all 59 PNG/RGBA pairs and reproduces all
saved diagnostics/control outcomes, including 30 additional passing control
payload attempts. The passive rank audit uses three retained PNGs and a
separately labeled diagnostic VM with observation-only snapshots. Its locator
returns match the ordinary implementation exactly. It is not an acceptance
reader. No expected corners, repaired pixels or tuned reader parameters.

All 241 phase-05 and 460 phase-04 inventoried files and all three original product
download hashes remain unchanged. Superseded executed sources are preserved.
New source/evidence/handback files stay below a fresh 6-MB logical-file cap.

18/18 product unit tests, full repository formatting, scoped-file and Git
whitespace checks pass. The headless HTML handback fits a 390-pixel viewport;
24 diagram combinations match retained traces, its checkpoint download is exact,
and simulated clipboard denial selects the correct prompt. No page errors or
automatic external requests. These are browser checks, not native clipboard or
phone acceptance. Product build/site/text-browser checks remain earlier results
on unchanged product code; downloads are not rebuilt or replaced.

## Deviations

Four capture aborts survive with manifests, controls and uncompleted entries:
whole-word packing, fixed-pitch tail tolerance, one source-width rejection, and
a dictionary-wide envelope guard on a frozen smaller glyph set. Exclusive
continuations preserve the original planned cases and source snapshots. Those
administrative entries are not extra failed scans. No rejected text is shortened.

The first retained-pixel checker rejects cross-VM object prototypes despite
matching RGBA hashes; its receipt is preserved and a serialized-value comparison
passes in a second fixed-input replay. The first passive audit exceeds its
internal uncompressed output guard before saving its counts. That abort is
explicit; a second audit saves all points/groups losslessly in gzip JSON for the
same three inputs. These checker/retention repairs do not change acceptance.

## Known issues

No accepted readable, inconspicuous, meaningful prose with ordinary-reader and
normal-phone recovery. Impact's heavy, crowded native letters and synthetic
T/E/H/F words are diagnostic relaxations. Center-axis improvement does not
establish two-dimensional finder formation, full payload recovery or legibility.
Phase-04 small-image replay still reproduces only six of eight earlier hashes.

No new phone, physical-print, Gmail, native clipboard or owner installed-extension
observations. Earlier phone-case denominator and viewing conditions remain
unknown. Emoji atlas and dedicated project migration remain deferred. The next
objective must address native two-dimensional finder geometry and legibility
before a bounded full-QR test. Research is incomplete.
